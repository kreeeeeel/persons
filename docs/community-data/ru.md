# Реальные данные каталога и ленты

Каталог `/{locale}/people` получает только опубликованные, неудалённые страницы через `GET /v1/persons/directory`. Имя, аватар, просмотры, число опубликованных фото и моментов и средняя оценка берутся из БД. Отсутствующая оценка отображается прочерком. Сортировки `VIEWS`, `RATING`, `NEWEST`, `NAME` применяются до пагинации; размер страницы ограничен 60. Запрос использует Criteria API и не делает отдельных запросов статистики на каждую карточку.

Лента `/{locale}/feed` использует `GET /v1/feed`, а не список демонстрационных страниц. Сервер объединяет существующие стены, комментарии к медиа, оценки, отзывы о займах, фото, моменты, достижения и матчи Dota/CS. Старые публикации доступны сразу: новая таблица событий и перенос данных не нужны. Все источники участвуют в общей сортировке и серверной пагинации. Поле `kind` фильтрует данные до пагинации; `GAME` включает обе игры. Для одинакового времени используется устойчивый порядок вида события, страницы и ID записи. Полезная нагрузка собирается пакетами только для выбранной порции.

Удалённые и неопубликованные страницы, ожидающие модерации материалы, скрытые медиа и комментарии к ним исключаются. Для CS сохраняются проверки срока снимка и актуальной Steam-ссылки. Права изменения и реакции рассчитываются для текущего пользователя. BFF передаёт сессию и фильтры через сгенерированный клиент и возвращает `private, no-store`. Ошибка сервера показывает ошибку с повтором, а не пустую ленту или демонстрационные данные.

Бегущая строка подключена один раз в `LocalizedContent`, поэтому присутствует на главной, страницах людей, в каталоге, ленте и других локализованных разделах. Сохраняются глобальные настройки, персональное скрытие, обе темы и уменьшенное движение. Нижний отступ учитывает высоту строки.

Фикстуры каталога и страниц находятся в `frontend/person/tests/fixtures`; рабочие модули не могут импортировать их — это проверяет ESLint. `COMMUNITY_PREVIEW` и URL-параметры сценариев больше не управляют production-лентой.

Проверки: `CommunityReadIntegrationTest` (исторические данные, видимость, статистика, сортировка, пагинация после 50 записей, обе игры, ограничения параметров), `loadFeedPage`, `DirectoryScreen`, BFF и общий слой строки. Для запуска интеграционного теста на отдельной PostgreSQL задайте `COMMUNITY_TEST_DB_URL`, `COMMUNITY_TEST_DB_USER`, `COMMUNITY_TEST_DB_PASSWORD`; по умолчанию используется H2. Полные проверки: `./gradlew ktlintCheck test bootJar` в `backend/person`, `npm run check` и `npm run build:testing` в `frontend/person`.
