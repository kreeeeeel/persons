# Персоны

`backend/person` — отдельный Spring Boot/Kotlin-сервис на 8085. Он хранит персон отдельно от аккаунтов ID. Публичные страницы открываются как `/{tag}`; Next.js переписывает адрес во внутренний локализованный маршрут, сохраняя чистый URL. Вход с такой страницы возвращает на ту же персону.

Поиск начинается после двух символов и паузы 350 мс. Старый запрос отменяется при новом вводе. Результаты содержат ФИО и аватар персоны, общий счётчик, скелетоны и пустое состояние. Enter открывает выбранный результат; стрелки меняют выбор, Escape закрывает список.

Профиль содержит описание, теги, кнопки Telegram/Steam/Discord, статистику и вкладки стены, оценок, моментов, фотографий, репутационных записей и достижений. Хедер фиксированный: в начале страницы прозрачный, при прокрутке получает фон темы. SegmentedTabs перенесён из smart house. Пустые состояния и элементы уведомлений без заливки. Сессии открываются модально из меню аккаунта; карточки и разделение устройств перенесены из smart house. Минимальный шрифт — 16px.

## Данные и согласование

В админке `/ru/settings` находятся независимые переключатели обязательной проверки текстов (стена, комментарии к медиа, отзывы к оценкам и займы), фотографий и моментов. По умолчанию все включены. Выключенный переключатель публикует новые материалы и применяет их изменения/удаления сразу, в одной транзакции через существующую логику согласования. Уже ожидающие заявки автоматически не пересматриваются. Для пользователя в разделе «Пользователи → Модерация» можно включить обязательную проверку: она имеет приоритет над общими настройками. Профили, аватары и подтверждение владения всегда проверяются. Настройки и автор изменения хранятся в PostgreSQL; API доступен только администраторам. Ответ операции содержит фактический `PENDING` либо `APPROVED`, и интерфейс показывает соответствующее сообщение.

Отправки блокируют строку персоны до вставки связанных записей и запросов, способных вызвать JPA flush. Это сохраняет единый порядок блокировок при автопубликации и ручном согласовании: PostgreSQL не приходится повышать FK-блокировку до `FOR UPDATE` после конкурентных вставок. Порядок покрыт регрессионными тестами.

Главная сначала показывает общий `PageLoader`: фон темы и вращающийся логотип. Клиент заранее загружает и декодирует все восемь иллюстраций слайдера. Повторные переходы используют общий кэш загрузки; версионированные публичные изображения получают годовой HTTP-кэш `immutable`. Ошибка отдельного изображения или ожидание дольше 12 секунд освобождают страницу, загрузки продолжаются в фоне. Личные фотографии и ответы API этим механизмом не кэшируются. При reduced motion логотип остаётся неподвижным.

Discord указывается тегом: username либо старый `имя#1234`, с необязательным `@`. В контракте SocialLink для него используется `tag`; для Telegram/Steam — `url`. Нельзя одновременно передать оба поля или указать тег для другой сети. Username нормализуется в нижний регистр, старый тег сохраняет регистр. Кнопка Discord показывает тег и копирует его; ошибки копирования видны пользователю. Старые HTTPS-ссылки Discord остаются совместимыми. Тег хранится в существующей строке социальной сети PostgreSQL и проходит обычную модерацию профиля.

Проверка username соответствует [правилам Discord](https://support.discord.com/hc/en-us/articles/12620128861463-New-Usernames-Display-Names): 2–32 символа, латиница, цифры, точки и подчёркивания; две точки подряд запрещены.

Отдельные таблицы: `persons`, теги, социальные ссылки, варианты эмодзи, оценки, комментарии, медиа, фотографии, моменты, лайки моментов, дневные просмотры, репутационные записи, заявки модерации и уведомления. Аккаунты остаются в ID; в person хранится UUID владельца/автора.

Создание, изменение профиля, привязка аккаунта, комментарии, репутационные записи, загрузки и удаления сначала попадают в модерацию. Публичные данные не меняются до согласования. Администратор просматривает содержание/медиа и согласует либо отклоняет с обязательной причиной. Автор получает уведомление; при удалении чужого материала уведомление получает и его автор. Повторное решение не применяется. Версия профиля предотвращает перезапись более свежих данных устаревшей заявкой.

Оценка — число от 1 до 5 и выбранный эмодзи, одна оценка на аккаунт и персону. Можно изменить значение/эмодзи или снять голос; API возвращает среднее, количество и собственный голос. Допустимые эмодзи задаются в профиле. Вариант с существующими голосами нельзя убрать. Миграция переносит прежние эмодзи-голоса как 5/5. Просмотры считаются один раз в сутки на HttpOnly-идентификатор браузера: API принимает их только от BFF с сервисным JWT, клиентский UUID в теле BFF игнорирует. IP для просмотров не сохраняется.

Репутация — enum `Reputation`: `UNKNOWN` при отсутствии отзывов, `GOOD` если согласованных записей о доверии больше, `BAD` если больше сомнений, `AVERAGE` при равенстве. UI показывает только перевод и соответствующий цвет. Денежных сумм и банковских данных нет. Старый `creditScore` оставлен в контракте как deprecated для совместимости.

## Медиа

Закрытый префикс S3 по умолчанию — `person-media/`. Ключи создаёт сервер. Аватары: PNG/JPEG до 2 МиБ, фотографии — до 32 МиБ; видео MP4/WebM — до 512 МиБ. Проверяются сигнатура и размеры изображений. Загрузка открывает новый поток для каждого чтения SDK, без буферизации всего видео в JVM. Неопубликованные файлы видят только загрузивший пользователь и администратор. Отклонённые/удалённые файлы и незавершённые загрузки старше суток очищаются фоновым заданием с повтором при сбое S3.

Multipart-загрузки проходят мимо клонирования тела в Next.js proxy: авторизацию и проверку Origin выполняет BFF, который передаёт тело потоком на фиксированный backend-маршрут. Общий предел запроса — 545 МиБ с учётом превью, тайм-аут передачи — 10 минут. Spring сохраняет части запроса во временные файлы, Nginx не буферизует загрузку целиком. В просмотрщике на широком экране комментарии и сортировка находятся справа; крупные стрелки расположены за границами окна. Переключение заменяет содержимое и URL медиа, сохраняя открытое окно.

Бинарные ответы идут потоково через BFF; поддерживаются одиночные обычные, открытые и suffix Range-запросы. Плеер реализует воспроизведение, паузу, перемотку, звук, скорость, полный экран, клавиатуру и повтор после ошибки. Gateway принимает загрузки до 65 МиБ. Брендовые иллюстрации находятся в публичном `assets/`, фотографии персон остаются приватными.

Фото и видео отображаются сеткой карточек без заливки, с подписью под превью. У видео справа снизу показана длительность `мм:сс`. При загрузке браузер измеряет длительность и создаёт JPEG-превью; сервер проверяет допустимые пределы и изображение, сохраняет их вместе с исходником в S3. Для прежних видео без превью используется первый кадр и длительность из браузера.

Общий просмотр располагает медиа сверху, затем название, автора и общий блок реакций, отмеченных персон и комментарии. Лайк и дизлайк взаимно исключаются, повторный запрос не размножает голоса. Комментарии к фото/видео хранят ссылку на медиа и отделены от стены; они также требуют модерации. Аватар и имя автора ведут на его привязанную персону, если она существует. Изменения текста комментария, репутационной записи, подписи и отметок тоже сначала согласуются. Отметки — ссылки на публичные персоны, до 20 на медиа. Старые моментные лайки и комментарии переносит миграция V2.

## Подтверждение страницы

У непривязанной страницы есть действие «Это моя страница». Неавторизованный посетитель проходит ID и возвращается к ней. Автор прикладывает объяснение 10–2000 символов и PNG/JPEG до 12 МиБ; заявка `CLAIM_OWNERSHIP` попадает в общую модерацию. Доказательство в S3 доступно только заявителю и администраторам, в том числе после согласования. Оно никогда не публикуется в галерее. Отклонённый файл удаляется фоновой очисткой.

После согласования аккаунт получает право редактировать персону, а на аватаре появляется галочка с пояснением. Один аккаунт может владеть одной страницей; уникальность дополнительно контролирует БД. Администратор может привязать или отвязать аккаунт вручную. Удаление персоны освобождает привязку. Решения приходят в уведомления.

## Админка и достижения

`http://localhost:3001/ru` — пользователи; боковое меню ведёт в персоны, модерацию и достижения. В `/ru/persons/{tag}` доступны изменение профиля и аватара, работа со стеной, репутацией, фото, видео и наградами. Пользовательские изменения и контент проходят модерацию; операции с определениями достижений выполняет администратор напрямую.

`AchievementService` внутри person хранит определения в `achievements`, выдачи — в `person_achievements`. Определение содержит изображение S3, название, описание, активность и версию. Администратор создаёт и редактирует его, меняет изображение, архивирует или восстанавливает. Массовая выдача ограничена 100 персонами за запрос и идемпотентна: повторные получатели не дублируются. Награду можно отозвать на странице управления персоной. Архивные определения не отображаются в публичных профилях. Заменённые изображения и незавершённые загрузки достижений учитывает `storage_garbage`, с повторной фоновой очисткой спустя сутки.

## Локальные демо-данные

Сначала поднимите Compose. Нужен FFmpeg в PATH либо `FFMPEG_BINARY` с путём к нему:

```powershell
node scripts/create-demo-video.mjs
node scripts/seed-demo.mjs
node scripts/seed-person-features.mjs
```

Скрипт явно создаёт один локальный аккаунт `demo@persons.local` с ролью ADMIN и случайным паролем. Реквизиты сохраняются только в игнорируемом `.build/person-demo-account.json`. Письма не отправляются, существующие аккаунты не заменяются. Скрипт использует сгенерированные клиенты и обычные заявки/решения API, повторный запуск не размножает опубликованные данные. Временная сессия скрипта отзывается в конце. Исходные фотографии читаются из `Desktop/люди`; путь можно задать через `DEMO_FRIENDS_DIR`.

Страницы: `/krel` — заполненная и привязанная к аккаунту; `/vadim` и `/tyamik` — частично заполненные, с хорошей и плохой репутацией; `/slava` и `/artem` — пустые состояния. У Крела репутация средняя. Социальные ссылки в демо ведут на общедоступные страницы платформ, а не на подтверждённые аккаунты друзей. Видео — восьмисекундная иллюстрация, не реальная съёмка. В очереди есть пример ожидающего комментария; в уведомлениях — согласованные и отклонённые записи.

Последний скрипт добавляет отметки к демо-медиа и достижения Крела/Вадима, сохраняя `/artem` пустым. Новые аккаунты не создаёт, письма не отправляет и отзывает собственную временную сессию.

`person-upload.spec.ts` дополнительно загружает настоящий `.build/demo-moment.mp4` через интерфейс, проверяет созданное JPEG-превью, длительность, отметки в модерации и публикацию, затем удаляет собственный тестовый момент через модерацию.

Проверки бэкенда: `ktlintCheck :app:api:test :app:api:bootJar :app:contract:client:build`. Фронтенды person/person-admin: `npm ci`, `npm run check`, `npm run build:prod`. Из person запустите `npx playwright test tests/e2e/person-domain.spec.ts tests/e2e/person-evolution.spec.ts` против локального Compose и указанных демо-данных: используется парольный вход, без писем. `E2E_LIVE_STACK` не нужен. Новые схемы операций: `gallery.yaml`, `claims.yaml`, `achievements.yaml`; TypeScript- и Kotlin-клиенты генерируются из общего контракта.

Общий `PersonIdentity` показывает аватар и имя в результатах поиска, выборе отмеченных людей и просмотре медиа; выбранные люди сохраняют аватары в поле. Поиск выбора людей использует задержку 350 мс. Формы редактирования, блокировок и выдачи достижений на сайте и в CMS ограничены шириной 400 px; на узких экранах занимают доступную ширину с внешними отступами.

Меню настроек плеера шириной 208 px прокручивает только варианты скорости/качества: кнопка возврата остаётся сверху. По отдельному требованию текст настроек — 14 px с весом 600; остальная типографика сохраняет минимум 16 px. Кнопки плеера имеют одинаковый размер 36 px. Действия редактирования и удаления медиа представлены иконками общего `ContentActions` справа на уровне реакций, с учётом серверных разрешений. Блоки реакций и скачивания сохраняют высоту 48 px с внутренним отступом 4 px. Результат фоновой загрузки отображается в карточке очереди на поверхности `--persons-surface`, без дублирующего баннера «Изменения сохранены». Ошибки операций остаются видимыми; отправка текста на модерацию отмечается спокойным статусом.

Новые правила видимости своих ожидающих модерации записей, комментарии к оценкам, списки авторов реакций, просмотры медиа, займы и заявки на свою страницу: [подробности](community_ru.md).
