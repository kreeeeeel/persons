# Ленты и ссылки на медиа

Фото ограничены 32 МиБ, видео — 512 МиБ, multipart-запрос — 545 МиБ. Маршрут `/api/person/v1/persons/{id}/media` в обоих фронтендах использует нативный Node API handler с `bodyParser: false`: поток идёт в backend с обратным давлением без преобразования в Web Request или FormData. Проверки Origin, сессии, UUID и размера сохраняются; backend проверяет доступ, ограничения пользователя и содержимое файла. Входящие Cookie не передаются backend. Остальные страницы и API остаются в App Router. Таймаут загрузки — 10 минут; nginx не буферизует тело запроса.

Запись файла в S3 получает отдельный таймаут 5 минут на запрос `PutObject`; общий короткий таймаут клиента остаётся для чтения и удаления. Иначе загрузка на малом VDS могла обрываться через 10 секунд уже после приёма файла backend. Регрессионный тест использует настоящий HTTP-клиент и замедленный ответ хранилища.

Проверка контейнера с лимитом 192 МиБ: видео 512 МиБ прошло до S3, чтение диапазона байтов совпало с исходником, пик памяти фронтенда — 91 МиБ, без OOM или перезапуска. Проверочный материал удалён штатным API.

Постраничные списки публичного сайта и CMS используют общий `useInfinitePersonData` и `InfiniteFeedLoader`. Следующая порция запрашивается при приближении к концу списка; во время запроса вращается логотип. Загруженные записи сохраняются. Ошибка следующей порции не скрывает список, повтор запрашивает ту же страницу. Поиск и фильтр начинают новую ленту с первой порции и отменяют устаревшие запросы. Ручное переключение страниц удалено; кнопка подгрузки остаётся только как доступный резерв для браузера без IntersectionObserver.

Публичная ссылка на фотографию: `/{tag}?photo={mediaUuid}`, на момент: `/{tag}?video={mediaUuid}`. Кнопка «Поделиться» копирует её, в том числе из CMS, используя публичный домен. Переход по ссылке открывает профиль, соответствующую вкладку и просмотр независимо от страницы загруженной сетки. В просмотре проверяются принадлежность медиа профилю и вид коллекции; доступ к неопубликованным материалам по-прежнему проверяет сервер. Для материала на модерации публичная кнопка отсутствует.

Открытие галереи добавляет одну запись истории браузера. Стрелки внутри галереи заменяют её; «Назад» закрывает просмотр, «Вперёд» открывает снова. При закрытии прямой ссылки параметры медиа удаляются без ухода с профиля. Остальные параметры сохраняются. Неверные UUID и неоднозначные параметры игнорируются.

`LoadedImage` отслеживает события самого изображения без отдельного `new Image()` с тем же URL. В каталоге достижений изображения загружаются лениво. Информация о текущем пользователе повторно используется только в пределах одного серверного рендера через React `cache`; данные разных запросов и аккаунтов не смешиваются.

Проверки: `npm run check` в `frontend/person`, `frontend/person-admin`, `frontend/id`. Тесты покрывают добавление порций, сброс поиска, повтор после ошибки, отсутствие ручного пейджера, ссылки/историю, несовпадение профиля/коллекции, модерацию и загрузку изображений.
