# Отзывы, медиа и личная страница

Все публичные и административные ручки находятся в `backend/person`. Управление аккаунтами проксируется в ID после проверки актуальных прав администратора. Отдельный backend `person-admin` больше не нужен.

Имена и аватары авторов комментариев, отзывов, займов, реакций и медиа берутся из актуального аккаунта ID одним пакетным запросом на страницу. Сохранённое имя используется только для отсутствующего аккаунта; аватар персоны не подменяет фотографию аккаунта. Версия аккаунта входит в URL аватара, ответы не кешируются. После смены фотографии открытые списки обновляются без очистки и закрытия модалок. Внутренние ручки профилей и аватаров требуют сервисный JWT; публичный BFF выдаёт аватары только участников проекта, без email, ролей и сессий.

В просмотре фото и видео комментарии расположены под медиа и его описанием, сортировка — справа над комментариями. Крупные стрелки остаются снаружи окна. Переключение заменяет содержимое, сохраняя открытое окно.

Полоса прокрутки проявляется при наведении на окно; зарезервированное место под неё исключает изменение ширины. Имя автора и просмотры находятся справа от аватара. Отдельный блок рядом с реакциями позволяет скачать оригинал или скопировать ссылку с коротким подтверждением. Переход по автору открывает его страницу, а для аккаунта без привязки выводится пояснение.

Фото и видео выбираются через общий `FileDropDialog`, затем открывают предпросмотр с подписью и отметками людей. Корневой `UploadQueueProvider` последовательно отправляет файлы через XHR с фактическим прогрессом и отменой. Последние три уведомления закреплены справа снизу; полный список открывается отдельно. Очередь продолжает работать при внутренних переходах сайта. Полная перезагрузка или закрытие вкладки прерывает передачу; при незавершённых файлах браузер предупреждает о выходе. Аватары используют общий редактор с обрезкой.

Шестерёнка плеера управляет скоростью и реальными вариантами качества. `person-worker` получает задания из PostgreSQL после загрузки видео, обрабатывает по одному файлу FFmpeg и сохраняет уменьшенные MP4 в приватный S3. Качества 360p, 720p и 1080p создаются только ниже исходного разрешения. При переключении сохраняются время и воспроизведение. Оригинал доступен во время обработки и при её ошибке. Задания имеют аренду, три попытки и повтор через пять минут; временные объекты S3 учитываются в существующей очереди очистки. Миграция V12 добавляет задания для существующих опубликованных и ожидающих проверки моментов.

Состав списков авторов реакций кэшируется на пять минут; права доступа проверяются на каждом запросе, актуальные имена и аватары подставляются отдельно. Изменение реакции сбрасывает страницы соответствующего материала после фиксации транзакции.

Кнопка с жуком открывает управление текущей страницей: профиль и эмодзи оценок, аватар, привязка аккаунта, ручная выдача достижений и репутация. Ручное значение репутации хранится отдельно от расчёта джобы. Режим «Автоматически» возвращает отображение вычисленной репутации.

В выборе достижений поиск учитывает название карточки; автоматические и отключённые награды отображаются недоступными для ручной выдачи. После немедленно опубликованного изменения тега сайт и CMS переходят на новый адрес без обращения к старой странице.

Миграция V4 добавляет комментарий к оценке, авторов реакций, отдельные просмотры медиа и признаки публикации комментариев и записей о займах. Число и эмодзи оценки обновляются сразу; её текст проходит модерацию. Автор видит собственный текст со статусом «На модерации», остальные — последнюю согласованную версию. Такое же правило применяется к стене и займам. Отклонённые новые записи исчезают из ленты автора. Удаление оценки отменяет её ожидающий модерации комментарий.

Просмотры фото и видео учитываются один раз в день для медиа и анонимного идентификатора устройства. Браузер не выбирает этот идентификатор: BFF хранит его в cookie. В PostgreSQL записывается HMAC, без исходного идентификатора. Лайки и дизлайки открывают отдельные списки авторов с пагинацией. Переход на страницу доступен, когда аккаунт связан с опубликованной персоной. Соседние медиа выбираются из той же персоны и того же вида, включая соседей за пределами текущей страницы сетки.

«Займы» используют enum `CreditKind`: `ON_TIME`, `SHORT_DELAY`, `LONG_DELAY`, `NOT_RETURNED`. Старые `TRUST` и `DOUBT` остаются в контракте для совместимости, существующие записи мигрируют на новые значения.

`GET /v1/persons/mine` возвращает подтверждённую личную страницу или состояние заявки. `POST /v1/persons/mine` создаёт заявку; один аккаунт может иметь одну действующую страницу. После согласования она получает отметку подтверждения. Пункт «Моя страница» открывает её либо экран с формой заявки и стандартным хедером. Смена почты и пароля использует существующие защищённые ID-ручки; почта подтверждается одноразовым кодом. Другие сессии завершаются по правилам ID.

Плеер, просмотр медиа, оценки, комментарии, займы и иллюстрации переиспользуются сайтом и админкой через `frontend/libs`. Изображения загружаются в S3 при `minio-init`. Итоговые иллюстрации и точные промпты записаны в [манифесте](../assets/community-generation.json); 404 сохранена. На восьми новых слайдах персонажи справа, слева оставлено место для интерфейса. Сцены с Никитой используют обновлённое фото.

Проверки: `./gradlew ktlintCheck test bootJar` в `backend/person`; `npm run check` и `npm run build` в обоих фронтендах. Браузерные сценарии запускаются против Compose. Для них достаточно входа существующей демо-учётной записью; отправлять письма через реальный SMTP не требуется.
