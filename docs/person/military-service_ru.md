# Даты профиля и общая галерея

Дата рождения, дата ухода в армию и ожидаемая/фактическая дата возвращения редактируются через общий редактор страницы, в том числе в CMS. Изменения используют существующие права доступа, версии и модерацию. Для старых страниц даты отсутствуют; фиктивные даты и статусы не подставляются.

На ПК слева остаются аватар, ФИО, просмотры и цветная оценка, карточки дат и таймер. Колонка закреплена при прокрутке; описание, вкладки и контент находятся справа. На телефоне блоки идут последовательно, длинное описание можно раскрыть. Навигация и аккаунт доступны через боковое меню. Иллюстрация главной расположена над поиском.

## Даты и границы дней

`PersonProfile.dates` содержит календарные `birthDate`, `militaryDepartureDate`, `militaryReturnDate`. Возраст и таймер рассчитываются относительно календарного дня `Europe/Moscow`. Статус выводится из дат: ожидание призыва, служба или возвращение. Уведомление «Уже дома» видно в день возвращения и следующие шесть дней; с седьмого прошедшего дня оно скрывается. Дата ухода сохраняется. Если дата возвращения неизвестна, длительность службы не угадывается.

В `ProfileInput` отсутствие `dates` сохраняет прежние значения, `{}` очищает все даты. Будущая дата рождения, уход до рождения и возвращение без ухода/до ухода отвергаются. Flyway `V27` добавляет nullable DATE-колонки, ограничения порядка дат и индекс общего списка медиа. Миграция не содержит контента.

## Медиа

`GET /v1/persons/{id}/gallery?page=0&size=12` возвращает одну страницу фото и моментов из `person_media`, с видом, просмотрами и данными существующей карточки. Порядок: `createdAt DESC, id DESC`. Видимость опубликованных и ожидающих модерации файлов совпадает с действующими правилами; чужие черновики, удалённые файлы, аватары и доказательства не попадают в галерею.

Вкладка «Фото и моменты» и CMS используют общий компонент `Gallery` с обычной пагинацией. «Загрузить» слева над сеткой сразу открывает общий выбор файлов. Можно выбрать фото и видео вместе; предпросмотр, подпись и отметки людей соответствуют текущему файлу. Сохраняются оригинальные формы и очередь загрузки. Счётчик просмотров находится справа сверху на превью, длительность видео — справа снизу.

Оригинальный `MediaViewer` сохраняет плеер, комментарии, реакции, автора, редактирование и ссылки `?photo=`/`?video=`. `GET /v1/media/{id}/details?mixed=true` возвращает соседей обоих видов и их типы, включая переход между страницами. Без `mixed=true` старые потребители сохраняют навигацию внутри одного вида. BFF передаёт параметр через сгенерированный клиент.

## Проверка

В `backend/person`: `./gradlew ktlintCheck :app:api:test :app:api:bootJar :app:contract:client:typescript:compileClient`. Также проверяются gateway и person-worker, зависящие от контракта и persistence-модели. В обоих фронтендах: `npm run check`, `npm run build:prod`.

`tests/e2e/profile-release.spec.ts` проверяет реальные локальные API: ru/en, обе темы, 320/390/1440 px, статусы службы, главную и меню, смешанную загрузку, исходные модалки, комментарии, стрелки, пагинацию и редактирование в CMS. Для отдельных локальных данных используется `node scripts/seed-profile-review.mjs --local-review` после запуска Docker-проекта `persons-feature` с обновлённым API, генерации клиентов и `node frontend/person/tools/create-feed-preview-media.ts`. Seed ограничен localhost и именованным локальным проектом, хранит служебные данные только в игнорируемой `.cache/`. Запуск: `E2E_REAL_PROFILE=true npx playwright test profile-release.spec.ts` из `frontend/person`, при работающих `npm run dev` на 3002 и 3001. Runtime страницы получает только реальные API-данные; армейский mock-preview удалён.
