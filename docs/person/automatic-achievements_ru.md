# Автоматические достижения и поиск

На внутренних страницах публичного сайта компактный поиск расположен справа от логотипа. На главной остаётся только большое поле слайдера. Оба варианта используют общий `PersonSearch` из `frontend/libs/person-domain`: минимум два символа, пауза 350 мс, отмена устаревшего запроса, скелетоны, пустое состояние, повтор при ошибке и управление клавиатурой.

## Способы выдачи

`AchievementType` — enum `MANUAL` / `AUTOMATIC` в OpenAPI и PostgreSQL. Старые определения после миграции V10 остаются ручными. Администратор выбирает способ выдачи при создании и редактировании. Для автоматического достижения обязателен `pageAgeYears` от 1 до 5; для ручного поле отсутствует. Ограничение проверяют контракт, сервис и CHECK базы. Старые клиенты, не передающие новые поля при обновлении, сохраняют существующее автоматическое правило.

Ручные достижения можно массово выдать максимум 100 персонам за запрос и отозвать у отдельной персоны. Автоматические выдаёт только `person-worker`; API отклоняет их ручную выдачу и отзыв. Архивирование скрывает достижение и останавливает новые выдачи. Изменение правила не отзывает уже полученные достижения.

## Джоба

`AutomaticAchievementJob` запускается через 30 секунд после старта, затем каждые пять минут. Настройки ISO-8601: `ACHIEVEMENTS_INITIAL_DELAY` и `ACHIEVEMENTS_DELAY`. Один запуск обрабатывает максимум 500 выдач, оставшиеся переходят на следующий запуск.

Учитывается полное число календарных лет от `persons.created_at` в UTC. Для страницы от 29 февраля годовщина в невисокосный год наступает 28 февраля в то же время. Выдаются все достигнутые пороги: пятилетняя страница может получить значки за каждый из пяти лет. Неопубликованные и удалённые страницы, архивные и ручные определения исключены. При публикации старой страницы подходящие награды появятся после очередной проверки.

Одно SQL-выражение выбирает ограниченный пакет и вставляет выдачи в транзакции. `FOR UPDATE SKIP LOCKED` защищает определения от конкурентного редактирования; существующая уникальность `(person_id, achievement_id)` и `ON CONFLICT DO NOTHING` предотвращают дубли при нескольких воркерах и повторных запусках. У системной выдачи `assigned_by = NULL`; ручная хранит UUID администратора.

## Каталог и импорт

Второй каталог `frontend/assets/achievements/community-jokes.json` добавляет одиннадцать ручных наград: «Долгожитель» (Никита), «Преданный слушатель Lil Peep», «Жирный» (Крел), «Вонючий» (Вадим), «Сексуальный» (Юрчик), «Каблук» и «Тюрьма» (обе с Евгением), «Онлайн-футболист» (Артём, REMATCH), «Деменция» (Никита), «Игрок в Доту» (Стёпа) и «Любитель уральских пельменей» (Вадим с табличкой шоу). Общий импорт проверяет все 20 изображений в S3; получателей новых наград выбирает администратор.

В `frontend/assets/achievements/anniversaries-and-habits.json` сохранены девять определений и точные промпты: юбилеи 1–5 лет, «Любитель выпить», «Любитель занимать», «Боится дневного света» и «Улетает со Старого Мельника» с лицом Вадима. Все изображения — отдельные PNG с прозрачностью. Метаданные/правила и выдачи хранятся в PostgreSQL, изображения загружаются штатным API в закрытый S3.

После генерации клиентов запустите `node scripts/seed-achievements.mts` на Node 24, передав окружение `SEED_ID_URL`, `SEED_PERSON_URL`, `SEED_EMAIL`, `SEED_PASSWORD`, `PROJECT_INTERNAL_JWT_SECRET`. Адреса указывают на шлюз с суффиксами `/id` и `/person`; прямой Person API защищён от обхода шлюза. Используйте SSH-туннель к действующему серверу для production. Не помещайте пароль или внутренний секрет в командную строку либо Git.

Импорт добавляет только отсутствующие определения этого каталога, не меняет существующие и не выдаёт ручные награды. При несовпадении существующих настроек останавливается. После загрузки проверяет байты каждого изображения, не создаёт персон или аккаунтов и отзывает собственную сессию. Повторный запуск должен сообщить `created: 0`, `alreadyPresent: 20`.

## Проверки

`npm test --prefix frontend/assets` проверяет уникальность записей обоих каталогов, правила выдачи, наличие квадратных PNG и их альфа-канал.

Person: `./gradlew build ktlintCheck`. Worker: `./gradlew build ktlintCheck`. Для PostgreSQL-тестов воркера задайте `WORKER_POSTGRES_TEST_URL` на отдельную тестовую PostgreSQL 18 с БД `worker_achievements_tests`, пользователем/паролем `tests`. Тесты удаляют только собственные фикстуры; не используйте production. В CI сервис PostgreSQL запускается автоматически.

Покрыты границы годовщин, 29 февраля, все пять порогов, исключения, пакетная обработка, конкуренция и повторные запуски. Frontend: `npm run check` в person и person-admin; тесты проверяют общий поиск, размещение в хедере, редактирование способов выдачи и отображение автоматической награды.
