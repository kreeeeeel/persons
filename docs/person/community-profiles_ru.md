# Статусы, авторы и справочник тегов

Общий редактор сайта и CMS имеет восемь разделов: основное, аватар, привязка аккаунта, описание и теги, армия, статус связи, поиск, социальные сети. Несохранённые поля сохраняются при переключении. Аватар и привязка открывают существующие диалоги; при создании страница сначала сохраняется. На телефоне раздел выбирается из списка.

`PersonProfile.presence` содержит `status` (`MISSING` или `UNRESPONSIVE`) и календарную `since`. Оба поля обязательны вместе; будущая дата запрещена. В `ProfileInput` отсутствие `presence` сохраняет значение, `{}` очищает. Статус отображается под таймером без рамки и не меняет права доступа.

`linkedAccount` раскрывает только публичные `id`, `handle`, `fullName`, `avatarUrl`, без электронной почты и настроек. Карточка ведёт к публикациям автора. `restriction` читается из сервиса блокировок: один блок над описанием содержит имя профиля, причину и срок. Кнопка информации без рамки показывает ограниченные действия при наведении, фокусе или нажатии. Полная блокировка перечёркивает имя. Недоступность сервиса блокировок возвращает 503.

## Публикации

`GET /v1/authors/me` возвращает свою публичную карточку, `GET /v1/authors/by-handle/{handle}` — карточку участника. Handle — тег опубликованной связанной страницы либо UUID аккаунта. `GET /v1/publications/by-author/{handle}` принимает `kind`, `page`, `size`; сайт подгружает страницы при прокрутке вниз. `/v1/publications/mine` сохраняется.

Страница `/{locale}/publications/{handle}` показывает аватар, имя и опубликованные материалы. Посетитель не видит чужие ожидающие модерации записи, черновики, удалённые записи и материалы на непубличных страницах. Свои ожидающие записи доступны автору. Реакции и права редактирования рассчитываются для посетителя.

## Справочник

`GET /v1/tag-definitions` возвращает определения. CMS `/{locale}/tag-dictionary` сохраняет весь справочник атомарно через `PUT /v1/admin/tag-definitions`. Доступ только администраторам. Максимум 200 тегов, 32 символа в теге, 500 в каждом описании ru/en. Нормализация приводит теги к нижнему регистру; дубликаты отвергаются без изменения данных. Комментарии, отзывы и займы разбиваются на безопасный текст и теги без HTML-инъекций. Значения доступны при наведении, фокусе и нажатии; неизвестные теги не получают выдуманных описаний.

## Ранг Dota и выкладка

OpenDota-парсер читает `players[].rank_tier` выбранного игрока, никогда `average_rank` матча. Отсутствующий или некорректный ранг не заменяется средним. Названия медалей локализованы. Flyway V28 добавляет статус связи, справочник и признак проверенного ранга. Старые неподтверждённые ранги скрываются; worker исправляет до пяти матчей при плановом обновлении интеграции, сохраняя статистику и инвентарь.

HTTP-клиент меняет порядок адресов из актуального DNS-ответа между попытками соединения. Это позволяет восстановиться, когда первый адрес принимает TCP-соединение, но зависает или обрывает TLS/ответ. IP вручную не закрепляются; ограничения числа попыток и проверка TLS сохраняются.

Person требует `RESTRICTIONS_BASE_URL` и общий доверенный service JWT; Compose передаёт адрес. Перед production-миграцией нужна резервная копия БД. Миграция не создаёт демонстрационные данные.

Проверки: `npm run check` в обоих фронтендах, тесты Person API, worker, gateway, dotabuff-integration; `E2E_REAL_PROFILE=true npx playwright test community-profile.spec.ts profile-release.spec.ts site-notices.spec.ts` на изолированном локальном стеке. Тесты изменения данных не запускаются на production.
