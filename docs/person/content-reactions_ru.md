# Реакции и сортировка текстовых лент

На стене, в отзывах с оценками, займах и комментариях фотографий и видео доступны лайк и дизлайк. У аккаунта может быть только одна реакция на запись. Выбор другой реакции заменяет предыдущую, повторное нажатие снимает её. Неавторизованные посетители видят счётчики, но не голосуют. Ограничение `REACTIONS` действует на оба вида реакции. Неопубликованные комментарии и займы, а также комментарии медиа на модерации недоступны для голосования.

Миграция V7 добавляет `reaction` в существующую таблицу `content_likes`. Старые строки получают `LIKE`; уникальность `(target_kind, target_id, user_id)` сохраняется. Индекс `(target_kind, target_id, reaction)` обслуживает счётчики и сортировку. Значения реакций — enum `LIKE`, `DISLIKE`.

Числовые счётчики статичны: наведение, фокус и нажатие не открывают списки проголосовавших. Иконка отдельно ставит или снимает реакцию. Это одинаково работает на стене, в оценках, займах, комментариях медиа, фото, видео и CMS. Публичные GET `/v1/content/{kind}/{id}/reactions` и `/v1/media/{id}/reactions`, компоненты списков и их серверный кэш удалены; запросы по прежним адресам возвращают 404. Голоса и счётчики в базе сохранены.

Историческая V8 добавляла снимок имени автора реакции и индекс. Эти данные остаются для совместимости миграций; API списков больше не предоставляется. Актуальные имена и аватарки авторов самих комментариев, оценок и займов по-прежнему подтягиваются из ID пакетно.

Новые ручки: `PUT /v1/content/{kind}/{id}/reaction` с `{"reaction":"LIKE"}` или `{"reaction":"DISLIKE"}`, и `DELETE` того же пути для снятия текущей реакции. Ответ содержит `count`, `liked`, `dislikes`, `disliked`. Старые GET/PUT/DELETE `/like` сохранены; старый DELETE снимает только лайк и не удаляет дизлайк.

В `GET /v1/persons/{id}/comments`, `/ratings` и `/credit` добавлен параметр `sort`: `NEWEST` (по умолчанию), `OLDEST`, `MOST_LIKED`, `MOST_DISLIKED`. Сортировка применяется на сервере ко всей доступной ленте до пагинации. При равных счётчиках сначала идут более новые записи, затем ID; у дат также есть дополнительный порядок по ID. Параметры страницы и ограничения видимости сохранены. Ответы включают `dislikes` и `dislikedByMe` вместе с прежними полями лайков.

Общие `ContentLike` и `FeedSortControl` используются в person и CMS. При смене порядка загруженные страницы сбрасываются, старый запрос отменяется; дальнейшая прокрутка загружает страницы выбранного порядка. Ошибка голосования сохраняет прежние счётчики и показывает сообщение. Числовые счётчики не имеют фона при наведении и не являются кнопками.

Пересчёт общей оценки и репутации по-прежнему выполняется воркером. Реакции на текст не изменяют формулу репутации: её определяют оценки из пяти и согласованные займы.

Проверки: `./gradlew ktlintCheck :app:api:test :app:api:bootJar` из `backend/person`; `npm run check` и `npm run build` из обоих фронтендов. Локальные браузерные сценарии находятся в `frontend/person/tests/e2e/person-polish.spec.ts`, сценарии сортировки и реакций создают временную персону и удаляют её после проверки, писем не отправляют.
