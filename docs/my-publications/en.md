# My publications

The authenticated `/en/my-publications` page is available in the account menu. Shared SegmentedTabs filter all publications, moments, photos, reviews, comments and loans. The page has no search field. The screen reuses feed cards, reactions, MediaViewer, timestamps, loading/error states and infinite pagination. MediaCommentCard shows the author, purple media type, destination page, photo/video icon, comment, reactions and time. Clicking the card or pressing Enter opens the shared MediaViewer; author/page links and reaction controls work independently. Media details load on opening. Pending content is labeled and unavailable reactions are hidden.

First, last and middle name inputs are limited to ten characters in registration, account settings, page editing and admin forms, with matching input API constraints. Existing names remain readable without truncation. Long feed and publication labels display the given name and family initial, preserving the full label in title. Formatting explicitly distinguishes family-first PersonSummary labels from given-first account author labels.

The feed includes a separate Comments event filter. `GET /v1/feed/comments` returns photo and moment comments across all public pages, independently of preview page sources. SQL checks comment, page and target media visibility before pagination, excluding hidden, deleted and pending content. Pending edits never replace published text. Pages, authors, media kinds and reactions load in batches rather than per card. Generated clients and the uncached BFF forward pagination and viewer identity. Cards reuse MediaCommentCard from My publications. The review adapter still merges bounded initial batches of different event types; a complete feed aggregator remains a separate task.

Migration V23 adds the global comment feed index on published, deleted, created_at DESC, id DESC. CommentEventsIntegrationTest verifies visibility before pagination, both media kinds, published text during pending edits, equal timestamps and anonymous access.

`GET /v1/publications/mine?kind=&q=&page=0&size=12` resolves the author from ActorResolver.required, never from a requested author ID. ContentCatalogDao shares the physical publication catalog with moderation, without duplicating gallery projections. SQL applies ownership, page visibility, kind and search before pagination. Drafts, deleted content and comments on removed media are excluded; pending submissions and the author's pending text edits are included. Ordering is created_at DESC, kind, id. Typed payloads load in batches. REPEATABLE_READ provides a consistent catalog/count/payload snapshot. Existing V11 author indexes suffice; no migration is needed. Server, Kotlin and TypeScript clients are generated from the contract.

The shared account menu displays a small borderless unread circle on the avatar and on the right of Notifications. It loads the existing notifications unread count at mount, when returning to the tab, and after reading or closing notifications. Zero is hidden; large counts display 99+ with an accessible full count. Failed requests preserve the last value. Public and admin menus share the same groups.

`GET /v1/persons/recommendations?size=5` samples random published pages, excluding deleted pages and those owned by the current account. The BFF does not cache the response. Every request samples again; randomness can produce repeats. A More people link remains below the list.

CMS INSTANT properties use Gravity DatePicker with calendar and time selection. Values display in Europe/Moscow and save as UTC ISO strings. Normalization does not mark the initial value dirty. Empty and invalid values cannot be saved.

Coverage includes MyPublicationsIntegrationTest, PersonRecommendationsIntegrationTest, PublicationsScreen, AccountMenu, FeedSidebar, VariableEditor and BFF tests. Set PUBLICATIONS_TEST_DB_URL, PUBLICATIONS_TEST_DB_USER and PUBLICATIONS_TEST_DB_PASSWORD to run the new integration tests on PostgreSQL; their default is test H2. Local review fixtures are served by tools/preview-api.ts; production uses generated clients.
