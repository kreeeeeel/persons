## Домены и конфигурация

Основной сайт — `kreeeeeel.ru`, ID — `id.kreeeeeel.ru`, CMS — `cms.kreeeeeel.ru`. HTTPS завершает Nginx; Next.js использует BFF для обращения к серверным API. Cookie сессии защищена и разделяется приложениями на общем домене.

Runtime-конфигурация исходного production находится в `/opt/persons/shared/.env`, релиз — `/opt/persons/current`. Реальные секреты в публичном репозитории отсутствуют. Для новой установки нужны собственные пароли, ключи S3, SMTP, домены и при необходимости Яндекс OAuth.

## PostgreSQL и Redis

Один кластер PostgreSQL обслуживает `id`, `person`, `restrictions`, `mail`, `i18n` и служебную `postgres`. Для полного восстановления нужны дампы всех баз и глобальные роли. Долговечный Redis хранит динамические свойства и их ревизии; второй Redis обслуживает кэш ограничений. PostgreSQL-дампы не заменяют копию Redis.

## Объектное хранилище

| Префикс | Данные |
| --- | --- |
| `assets/` | Публичные иллюстрации, логотипы и иконки |
| `avatars/` | Аватары аккаунтов и персон |
| `photo/` | Фотографии и превью |
| `video/` | Видеомоменты, превью и варианты качества |
| `achievments/` | Изображения достижений; исходное написание сохранено |
| `proofs/` | Приватные доказательства владения страницами |

Публичен только `assets/*`. Остальные файлы выдаются через API с проверками. При восстановлении сохраняйте ключи объектов, метаданные и приватность; не публикуйте весь bucket. [Хранилище](../deployment/storage_ru.md).

## Почта и фоновые задачи

SMTP настраивается отдельно, Mail service сохраняет очередь в PostgreSQL. Worker занимается расчётами, сроками, интеграциями и удалением объектов из очереди. При восстановлении сначала проверьте SMTP, очереди и задания в изолированной среде: старые задания не должны неожиданно отправить реальные письма или удалить файлы.

## Исходный CI/CD

GitLab остаётся источником оригинальной истории и конфигурации pipeline. В multi-repo окружении `workspace.lock` фиксирует точные ревизии, граф входов выбирает только изменившиеся образы, Registry хранит теги по содержимому. Общая интеграция включает backend/frontend-проверки и развёртывание на VDS.

Сохранённые `.gitlab-ci.yml`, `ci/` и `.gitmodules` относятся к исходной GitLab-топологии; их нельзя считать готовым GitHub Actions pipeline. Публичная копия предназначена для просмотра, локальной сборки и сохранения исходников.
