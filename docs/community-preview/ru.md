# Документы, каталог и переменные

Новые маршруты person: `/{locale}/privacy`, `/{locale}/terms`, `/{locale}/people`, где `locale` — `ru` или `en`. Страницы используют общий хедер главной. На узких экранах оглавление раскрывается через Gravity Disclosure. Переключатель языка находится в самих документах. Ссылка конфиденциальности получает фон при наведении и фокусе. Каталог доступен из подписи под поиском на главной.

Каталог использует реальные опубликованные страницы и статистику из БД. Сортировка и пагинация выполняются сервером. Фикстуры из `tests/fixtures` доступны только инструментам локального просмотра и тестам. См. [Реальные данные каталога и ленты](../community-data/ru.md).

В email-регистрации ID добавлен обязательный, заранее не отмеченный чекбокс принятия условий. Рядом с чекбоксом остаётся только ссылка на условия, без цветной подложки и поясняющего текста. Ссылки сохраняют язык и направляются через сервер на настроенный `PERSON_PUBLIC_URL`, без жёстко заданного production-домена. Это прототип интерфейса: хранение версии принятого документа и времени принятия на сервере, а также отдельный сценарий принятия при первом входе через OAuth ещё не реализованы.

Документы отображаются без статуса проекта и служебных предупреждений; индексация остаётся закрытой на этапе макета. Размещение данных в России указано по подтверждению владельца сервиса. Для окончательной публикации нужны реальные реквизиты оператора, почта, подтверждённые сроки хранения и удаления, фактические подрядчики, места обработки и применимые правовые основания. Принятие условий не объединено с согласием на любые операции с персональными данными или их распространение. Правила учитывают страницы третьих лиц, фото, отзывы, займы, ИИ-контент, обращения без аккаунта и обжалование модерации. Юридические страницы доступны также при блокировке аккаунта.

## Переменные

Типизированные объявления, контракт, Redis и обновления памяти перенесены в backend/libs/dynamic-properties. Фронтенд использует отдельную frontend/libs/dynamic-properties с URL и SSE. SQL-реестр и периодический опрос удалены. CMS использует библиотечный API с ревизиями; legacy settings API сохранены.

[Жизненный цикл, примеры, подключение и правила](../game-integrations/ru.md).

## Локальный предпросмотр

После установки локальных пакетов и генерации клиентов:

```powershell
# Из корня persons. Порты 3000, 3001, 3002, 4310 должны быть свободны.
./scripts/start-community-preview.ps1
```

Для более лёгкого просмотра без dev-компилятора сначала выполните `npm run build:testing` в каждом из `frontend/id`, `frontend/person-admin`, `frontend/person`, затем запустите:

```powershell
./scripts/start-community-preview.ps1 -Built
./scripts/stop-community-preview.ps1
```

Скрипт запускает только loopback-слушатели и не подключается к рабочим сервисам. Мок-API написан как инструмент предпросмотра (`frontend/person/tools/preview-api.ts`), его значения хранятся только в памяти и сбрасываются при перезапуске. Контакты `example.test` и демонстрационная сессия не являются настоящими реквизитами или аккаунтом. Письма не отправляются, пользователи в рабочей БД не создаются. Логи и PID с временем запуска находятся в `%TEMP%/persons-community-preview` вне наблюдаемого дерева Next.js.

- Главная: http://localhost:3002/ru
- Каталог: http://localhost:3002/ru/people
- Документы: http://localhost:3002/ru/privacy и http://localhost:3002/ru/terms
- ID: http://localhost:3000/ru
- Вход в демонстрационную админку: http://localhost:4310/session

Вместо `ru` можно использовать `en`; для английской админки — `/session?locale=en` на мок-API.

Проверки: `npm run check` в трёх приложениях, `:app:api:test` и `:app:api:ktlintCheck` в backend/person. Новый браузерный набор запускается только на мок-стенде:

```powershell
cd frontend/person
$env:E2E_MOCK_PREVIEW = 'true'
npm run test:e2e -- tests/e2e/legal-directory.spec.ts --timeout=120000
```

## Cookie и срок хранения удалённых медиа

Нижний баннер предлагает разрешить необязательный идентификатор учёта просмотров. До согласия и при отказе BFF не отправляет событие просмотра и не выдаёт PERSONS_VISITOR. Выбор сохраняется отдельной необходимой cookie на год; отказ удаляет прежнюю cookie посетителя. Сайт остаётся доступным. Кнопка в разделе cookie политики открывает выбор повторно. POST /api/cookie-preferences проверяет Origin и допустимые значения; ошибки сохранения не скрывают баннер.

MAP и JSON в CMS открываются кнопкой «Посмотреть» в отдельном окне только для чтения. Редактор CodeMirror 6 предоставляет подсветку JSON, номера строк, сворачивание, поиск, историю изменений и диагностику синтаксиса. Есть форматирование; невалидные значения нельзя сохранить. Цвета используют токены Gravity обеих тем.

Flyway V20 добавляет deleted_at страницам и медиа. Дата записывается при одобренном удалении, отклонении медиа и замене аватара. Для исторических удалений без известной даты срок начинается в момент миграции. Worker сохраняет удалённые медиа и retired-объекты до пяти календарных лет с даты удаления, затем удаляет исходник, превью и варианты качества. Для действующих медиа срок от загрузки не назначается. Незавершённые загрузки без привязки по-прежнему очищаются спустя сутки. Блокировки и повтор после ошибки S3 сохранены. В рабочем S3 настройки не менялись и удаление не запускалось.

Это срок для закрытых удалённых медиа, а не универсальное основание хранить любые персональные данные пять лет. Политика предусматривает более раннее уничтожение при утрате основания или обязательном требовании. Автоматизация индивидуальных юридических обращений и сроки очистки данных ID/журналов/резервных копий требуют отдельной реализации. Обычная S3 Lifecycle expiration считает срок от создания объекта, поэтому TTL реализован через дату удаления в БД и существующий worker: [AWS](https://docs.aws.amazon.com/AmazonS3/latest/userguide/lifecycle-expire-general-considerations.html). Оговорка о более раннем уничтожении учитывает [статью 21 152-ФЗ](https://www.consultant.ru/document/cons_doc_LAW_61801/d3fe43a7c415353b17faab255bc0de92bea127da/).

Таблица переменных использует общий ListTable для скругления, отступов крайних ячеек и состояния загрузки. Общий ActionTable поддерживает как меню действий, так и непосредственное открытие редактора. В переменных нет отдельной колонки действий: клик по строке открывает редактирование, а кнопка просмотра JSON работает независимо.

Баннер cookie монтируется после локализованного содержимого и включает кнопки после гидратации. Он не показывается в загрузочном fallback, поэтому ранний клик не теряется при замене загрузочного экрана. Полоса прокрутки оглавления скрыта до наведения или фокуса внутри меню.
