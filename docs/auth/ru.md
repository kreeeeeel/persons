# Авторизация

Экраны входа и восстановления используют одну прозрачную колонку по центру страницы: логотип, локализованный заголовок и форма. На экране входа после основных действий идут разделитель и кнопка Яндекс ID. Здесь нет боковой иллюстрации, шапки, футера и переключателей языка или темы. Локаль определяется URL, тема — общей настройкой приложения; текст остаётся не меньше 16px.

Регистрация: данные → код из письма → подтверждение → пароль и необязательный аватар → сессия. Аккаунт создаётся после подтверждения почты. Восстановление использует отдельный challenge и отзывает существующие сессии. Изменение почты и пароля доступны в API аккаунта; интерфейс настроек не входит в этот этап.

Пароль: минимум 10 символов, максимум 72 UTF-8 байта; BCrypt с cost 12. Сессия: подписанный JWT и хеш токена в PostgreSQL, проверка отзыва на каждом запросе, срок 30 дней. Cookie `PERSONS_SESSION`: HttpOnly, SameSite=Lax, Secure для HTTPS-адреса приложения. Браузер не получает сервисный JWT. Server Actions проверяют входные схемы, Next.js проверяет origin; backend независимо проверяет DTO и доступ.

Код: шесть цифр, HMAC-хеш с pepper, 10 минут, пять попыток, повторная отправка через 60 секунд. Ограничены попытки входа по IP и аккаунту. Пять неверных паролей блокируют вход на 15 минут. Временные почтовые сбои обрабатываются persistent outbox, код не попадает в логи.

OAuth реализует `oauth/OAuthProvider`; Яндекс — `oauth/impl/YandexOAuthProvider`. Одноразовая попытка хранит хеш state, хеш привязки браузера, verifier и срок действия. Повторный callback, чужая cookie и истёкшая попытка отклоняются до выдачи сессии. Внешний HTTP-запрос не удерживает транзакцию БД. Провайдерский access token не сохраняется и не возвращается браузеру. Совпадение почты не является основанием для связывания аккаунтов.

`USER` и `ADMIN` хранятся в аккаунте, статус — `ACTIVE`/`BLOCKED`. Административные операции доступны через отдельный backend, но ID проверяет актуальную роль и сессию. Изменение роли/статуса отзывает все сессии. Транзакция блокирует администраторов в стабильном порядке и защищает последнего активного администратора. Bootstrap выбирает только уже существующий подтверждённый аккаунт по настроенной почте.

Основной контракт: [ID OpenAPI](../../backend/id/app/contract/api/schema/api.yaml), [Admin OpenAPI](../../backend/person/app/contract/api/schema/api.yaml). Swagger доступен в dev/testing и отключён в production. Не передавайте внутренние сервисные ключи в браузер или публичный proxy.

Регрессии проверяют регистрацию, коды, восстановление, сессии, права, блокировки, OAuth replay/binding/expiry и конфликты почты. Яндекс проверяется локальным HTTP stub; настоящий внешний вход требует реквизитов приложения.
