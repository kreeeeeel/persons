# Те ещё люди

Локальный проект про друзей, их характеры и истории: ID, страницы персон, оценки с отзывами, стена, фото и видео, займы, достижения и модерация. Публичный сайт и админка используют общий backend/person. [Последние изменения и проверки](docs/person/community_ru.md).

## Быстрый запуск

Проекты находятся в [группе «Те ещё люди»](https://gitlab.com/te-eshche-lyudi). `infrastructure` собирает рабочее окружение из отдельных репозиториев через Git submodules. Нужен доступ к приватной группе.

```sh
git clone --recurse-submodules https://gitlab.com/te-eshche-lyudi/infrastructure.git persons
cd persons
```

Если репозиторий уже склонирован: `git submodule update --init --recursive`. Зафиксированные версии компонентов сохраняют воспроизводимый checkout. После изменения компонента сначала отправьте его commit в собственный проект, затем обновите gitlink в `infrastructure`. `git submodule update --remote --merge` явно обновляет окружение до текущих основных веток.

Нужны Docker Desktop с запущенным Linux Engine и Docker Compose v2. Команды выполняются из корня `infrastructure`:

```powershell
./scripts/setup.ps1
# Укажите PERSONS_ADMIN_EMAIL в созданном .env, если нужна админка.
docker compose up --build -d
docker compose ps
```

Сборка из чистого checkout генерирует API и устанавливает зависимости внутри контейнеров. Локальные JDK и Node.js для этого не требуются. Первый запуск требует доступа к Maven Central и npm.

| Что | Адрес |
| --- | --- |
| Главная person | http://localhost:3002/ru |
| Вход и регистрация | http://localhost:3000/ru |
| Администрирование | http://localhost:3001/ru |
| Письма для локальной разработки | http://localhost:8025 |
| MinIO Console | http://localhost:9001 |
| Backend ID | http://localhost:8081/actuator/health |
| Backend gateway | http://localhost:8087/actuator/health |
| Backend restrictions | http://localhost:8088/actuator/health |

Порты привязаны к `127.0.0.1`. Пароли и ключи генерируются скриптом в игнорируемый `.env`; скрипт сохраняет существующий файл. Для Linux можно скопировать `.env.example` в `.env` и заменить все примеры случайными значениями.

ID, person и админка локально используют общую cookie на `localhost` с разными портами. Для production предусмотрены основной домен, `id.` и `cms.`, общая защищённая cookie `SESSION_COOKIE_DOMAIN` и [Nginx с HTTPS](docs/deployment/nginx_ru.md). Локальный `web-gateway` направляет запросы к Next.js; production открывает Next.js только на loopback для хостового Nginx. Все BFF обращаются к ID и Person через отдельный Kotlin `gateway`, проверяющий блокировки.

## Регистрация и первый администратор

1. Нажмите «Создать аккаунт», заполните имя и почту.
2. Введите шестизначный код из письма. При настроенном внешнем SMTP письмо приходит на указанную почту; при стандартной локальной конфигурации откройте Mailpit.
3. Задайте пароль, при желании выберите и обрежьте аватар.
4. Если почта совпадает с `PERSONS_ADMIN_EMAIL` и активных администраторов ещё нет, в течение пяти секунд сервер присвоит роль `ADMIN`. Обновите страницу и откройте админку.

Произвольный пользователь не может передать себе роль при регистрации. Не создаётся ни готового администратора, ни общего пароля. После первоначального назначения уберите `PERSONS_ADMIN_EMAIL` из конфигурации и пересоздайте ID: `docker compose up -d id`.

Админка поддерживает поиск и пагинацию, роли `USER`/`ADMIN`, блокировки и завершение сеансов. Изменение роли завершает сеансы аккаунта. Через CMS нельзя полностью заблокировать себя или снять с себя роль администратора. Роль хранится и проверяется через ID; блокировками владеет `backend/restrictions`, а шлюз проверяет их до Person. Контракт администрирования аккаунтов сохранён в шлюзе; контентные админские ручки остаются в Person. При полной блокировке ID-сессия сохраняется для отображения причины и выхода из аккаунта. [Устройство и обновление](docs/deployment/restrictions_ru.md).

Создание и изменения от администратора публикуются сразу с записью в журнале модерации. Для обычных пользователей действуют настройки публикации и персональный режим обязательной модерации. В формах создания и редактирования персоны нет настройки оценок: пользователь выбирает эмодзи при написании отзыва. Существующие варианты сохраняются при редактировании страницы.

На странице персоны администратору доступно закреплённое меню с жучком: редактирование, аватар, привязка аккаунта, репутация, достижения и блокировки владельца. Управление блокировками получает актуальный привязанный аккаунт через защищённую ручку; для страницы без владельца сначала предлагается привязка.

Сайт, ID и CMS продлевают действующую сессию через защищённый BFF. За семь дней до истечения ID меняет токен и продлевает сессию, сохраняя устройство в списке. Старый токен принимается ещё 60 секунд для одновременных запросов вкладок. Истёкшие и отозванные сессии не восстанавливаются; свежий неизменившийся токен повторно не записывается в cookie.

Production-контейнеры Java используют `restart: unless-stopped` и `-XX:+ExitOnOutOfMemoryError`: JVM завершается при нехватке памяти, после чего Docker перезапускает сервис. В малом профиле лимит Metaspace составляет 192 МБ. Проверка здоровья сама по себе контейнер не перезапускает.

## Яндекс ID

Реализация подключена; для реального входа нужны ваши реквизиты приложения.

1. Создайте [приложение для авторизации пользователей](https://oauth.yandex.ru/client/new/id/), выберите платформу «Веб-сервисы». Запросите права `login:info` и `login:email`.
2. Production Redirect URI: `https://id.kreeeeeel.ru/api/oauth/yandex/callback`. Для отдельного локального окружения добавьте `http://localhost:3000/api/oauth/yandex/callback` и используйте его в локальном env.
3. Заполните `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET`, `YANDEX_REDIRECT_URI` в `.env`. Секрет остаётся на backend.
4. При смене доменов измените `PUBLIC_ID_URL`, `PUBLIC_ADMIN_URL` и `PUBLIC_PERSON_URL`, затем выполните `docker compose up -d --force-recreate id id-web person-admin-web person-web`.

Используются Authorization Code, PKCE S256, случайный одноразовый `state` и привязка к HttpOnly-cookie браузера. Обмен кода и получение данных выполняет backend. Привязка строится по стабильному ID Яндекса. Совпавшая почта существующего аккаунта не приводит к автоматическому объединению: пользователь должен войти по паролю или восстановить доступ. Отдельный интерфейс привязки провайдера в этот этап не входит.

Без реквизитов кнопка отображается, а попытка входа возвращает понятное сообщение о недоступности. Реальный вход с Яндексом можно проверить после регистрации вашего OAuth-приложения. [Официальный протокол](https://yandex.ru/dev/id/doc/ru/codes/code-url), [получение профиля](https://yandex.ru/dev/id/doc/ru/user-information).

## Структура

```text
frontend/id                 Next.js: вход, регистрация, восстановление, профиль и сеансы
frontend/person             Главная, поиск персон, профили, медиа и модальные сессии
frontend/person-admin       Отдельное приложение администратора
frontend/assets             SVG-бренд, favicon, Golos Text и исходные брендовые изображения
frontend/libs               Общие theme, i18n, photo-editor, UI
backend/id                  Kotlin/Spring Boot: аккаунты, OAuth, сессии, права и S3
backend/person              API персон, контента и модерации
backend/gateway             Проверка запретов и потоковое проксирование ID/Person
backend/restrictions        Блокировки, сроки и Redis-кэш; отдельная база restrictions
backend/person-worker     Фоновые расчёты оценок и репутации, истечение банов и очистка S3
backend/mail                SMTP-отправка через постоянную очередь
backend/i18n                Каталоги переводов, включая письма
backend/libs                Контекст авторизации и наблюдаемость
docker-compose.yaml         Общий запуск
```

Основа авторизации, тем и фото перенесена из smart house и адаптирована под `com.persons`. OpenAPI в `app/contract/api/schema` — источник серверных интерфейсов, Kotlin- и TypeScript-клиентов. Generated-код не хранится в Git.

## Хранение и почта

Все отображаемые брендовые изображения и аватары доставляются из S3. Compose запускает MinIO и загружает брендовые файлы в `persons/assets/`. Только этот префикс доступен публично. Префикс `avatars/` приватный; аватар выдаётся через авторизованный backend/BFF. Исходные фотографии друзей не включены в репозиторий. Favicon и шрифт поставляются вместе с приложением.

Для внешнего S3 применяется `docker/compose.external-s3.yaml` и профиль хранения `external`. Категории объектов: `achievments/`, `video/`, `photo/`, `avatars/`, приватные `proofs/` и публичные `assets/`. Удалённые медиа и заменённые/удалённые достижения очищает worker через очередь БД с повторами; ID очищает свои заменённые аватары. Базы `id`, `person`, `restrictions`, `mail` и `i18n` разделены внутри общего PostgreSQL-кластера.

Аватар временно попадает в надёжную очередь переноса в БД, затем фоновой задачей записывается в S3 и удаляется из БД. Это позволяет повторить перенос при сбое S3. Постоянное хранилище изображений — S3. Статический BFF `/media/` разрешает только заранее заданные брендовые объекты.

Без SMTP-настроек в `.env` Compose отправляет письма в Mailpit. Для настоящей отправки заполните там `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_AUTH`, `SMTP_STARTTLS`, `SMTP_STARTTLS_REQUIRED` и `MAIL_FROM`, затем пересоздайте только почтовый сервис: `docker compose up -d --no-deps mail`. Эти настройки передаются контейнеру явно и не попадают в образ. Письмо с кодом — локализованный HTML с фиолетовым оформлением. У внешнего домена отправителя должны быть настроены параметры, требуемые SMTP-провайдером. Обе очереди сохраняют задания в PostgreSQL и повторяют доставку при временных сбоях.

## Разработка и проверка

Локально нужны JDK 21, Node.js 24.11.1 и npm 11. Сначала сгенерируйте клиенты, затем устанавливайте frontend-зависимости:

```powershell
cd backend/id
./gradlew.bat generateClients
cd ../i18n
./gradlew.bat generateClients
cd ../person
./gradlew.bat generateClients
cd ../../frontend/id
npm ci
npm run check
npm run build:prod
cd ../person
npm ci
npm run check
npm run build:prod
cd ../person-admin
npm ci
npm run check
npm run build:prod
cd ../..
./scripts/check-backend.ps1
./scripts/tests/setup.test.ps1
```

`npm run dev` запускает ID на 3000, админку на 3001, person на 3002. Приложениям нужны адреса backend из соответствующих `.env.example`. Три frontend-профиля: `APP_ENV=dev|testing|prod`. Сборка Next.js не требует runtime-секретов; при запуске они проверяются. В Docker используется `prod`, у Spring — `production`.

Для быстрой проверки уже собранных локальных артефактов: `docker compose -f docker-compose.yaml -f docker/compose.prebuilt.yaml up --build -d`. Обычный `docker compose up --build` собирает всё из исходников.

Подробнее: [Docker и Podman](docker/DOCKER_ru.md), [главная person](docs/person/ru.md), [авторизация](docs/auth/ru.md), [ассеты и промпты](docs/assets/ru.md), [английская версия](README_en.md).

GitLab, CI/CD, подготовка VDS и команда `op почта`: [инструкция деплоя](docs/deployment/ru.md). Production использует `kreeeeeel.ru`, `id.kreeeeeel.ru` и `cms.kreeeeeel.ru`. Серверные реквизиты, включая SMTP и Яндекс ID, находятся в `/opt/persons/shared/.env` и не входят в Git. CI работает на project runner «Persons desktop Docker» с тегом `persons-local`; для сборок должны быть включены ПК и Docker.

## Персоны и локальное демо

Админка на `http://localhost:3001/ru` использует левое меню: пользователи, персоны, модерация, достижения. В профилях — оценки из пяти с выбором эмодзи, общая галерея фото/видео с отметками людей, лайком/дизлайком и комментариями. Привязку страницы можно запросить с приватным доказательством. После базового демо запустите `node scripts/seed-person-features.mjs`, чтобы увидеть отметки и выданные достижения.

Оценки других людей доступны всем через `GET /v1/persons/{id}/ratings` с пагинацией. Палитра из 96 эмодзи приходит в `RatingState.availableEmojis`; можно отправить `emoji` вместо настроенного `optionId`. Одна учётная запись оставляет одну изменяемую оценку. Миграция V3 сохраняет прежние оценки и их эмодзи.

Достижения в профиле открываются нажатием на изображение или название: описание и дата выдачи находятся в модальном окне. Их метаданные и выдачи хранятся в PostgreSQL, PNG с прозрачностью — в S3. Тридцать два актуальных значка и промпты встроенного image_gen сохранены в `frontend/assets/achievements`. Скрипт демо добавляет исходные двенадцать; новые каталоги из двадцати наград импортируются отдельно. В CMS доступны ручная выдача и автоматические годовщины страниц от одного до пяти лет. [Правила, джоба и импорт](docs/person/automatic-achievements_ru.md).

[Модель, API, модерация, плеер и создание демо-данных](docs/person/domain_ru.md). Заполненная страница: `/krel`, частичные: `/vadim`, `/tyamik`, пустые: `/slava`, `/artem`. Демо-аккаунт создаётся только явным `node scripts/seed-demo.mjs`; пароль находится в игнорируемом `.build/person-demo-account.json`. Скрипт не отправляет писем. [Иллюстрации и промпты](docs/assets/person-states.md).

В разделе «Пользователи» админки доступна кнопка «Блокировки»: можно запретить отдельные действия или весь проект, указать причину и дату окончания либо выбрать бессрочное ограничение. При попытке запрещённого действия появляется объяснение с Вадимом в полицейской форме; полная блокировка ведёт на `/ru/blocked` или `/en/blocked`. Истёкшие ограничения перестают действовать автоматически. Собственную полную блокировку администратор установить не может.

Миграция V5 хранит ограничения и лайки комментариев, отзывов и займов в PostgreSQL. Лайки идемпотентны: повторный запрос не увеличивает счётчик. Собственные фото и видео на модерации доступны автору с соответствующим тегом; до согласования реакции, комментарии и учёт просмотров отключены на сервере. Иллюстрации пустых фотографий, займов и блокировок находятся в S3; промпты записаны в `docs/assets/final-polish-generation.json`.

`ADMIN_PUBLIC_URL` в frontend/person задаёт адрес пункта «Админка» в меню администратора. Общие компоненты блокировок, выбора файла, лайков, галереи и плеера переиспользуются основным сайтом и CMS.

`person-worker` запускается общим Docker Compose. Оценки и согласованные займы влияют на репутацию с весами 60% и 40%; итоги пересчитываются фоновым заданием. Публичные ленты и списки в модальных окнах подгружаются при прокрутке с общим лоадером. [Очередь, формула, интервалы заданий и проверки](docs/person/background-jobs.md).

Комментарии, отзывы и займы поддерживают взаимоисключающие лайки и дизлайки. В этих лентах доступны четыре серверных порядка: новые, старые, больше лайков и больше дизлайков. Компоненты общие для сайта и CMS. [API, миграция и правила сортировки](docs/person/content-reactions_ru.md).

Основной сайт, ID и CMS используют общий счётчик Яндекс Метрики `113741427` только в production и после согласия на необязательные cookie. [Настройки, ограничения и проверка](docs/analytics/ru.md).

Персистентность production-кода использует Spring Data JPA и Criteria API. Общие сущности API и worker находятся в `backend/person/app/maintenance`; JDBC templates и native SQL запрещены проверкой `node scripts/check-persistence.mjs`. [Leetify: настройка, API и ограничения](docs/game-integrations/ru.md#leetify--counter-strike-2).
