# Настройки аккаунта и S3

POST /account/v1/email принимает новый адрес, текущий пароль и locale. Перед отправкой проверяются пароль и доступность адреса. Challenge имеет purpose CHANGE_EMAIL и user_id владельца. Код проверяется обычным endpoint challenge/verify; полученный grant используется POST /account/v1/email/complete. Grant одноразовый, ограничен владельцем, адресом, сроком и назначением. Во время изменения адрес повторно проверяется под блокировкой аккаунта; конфликт откатывает расходование grant. Другие сеансы завершаются.

PUT /account/v1/password принимает currentPassword и password. Новый пароль не короче 10 символов и не длиннее 72 байт UTF-8. Проверка текущего пароля использует существующую защиту от перебора. Под блокировкой пароль проверяется повторно, затем hash заменяется; текущий сеанс сохраняется, остальные отзываются. Пароли и grants не журналируются.

DELETE /v1/sessions/others отзывает только другие сеансы текущего пользователя. Одиночный DELETE /v1/sessions/{id} может завершить текущий сеанс. Регион сохраняется из X-Client-Region только при валидном сервисном JWT; без доверенного GeoIP gateway остаётся пустым. Интерфейс показывает неизвестный регион или локальную сеть.

id напрямую работает с AWS SDK S3, включая VK Cloud. Настройки — app/api/docker/.env, исключённый из Git; образ не содержит credentials. Существующие avatar_object_key сохраняются. JPEG сначала надёжно записывается вместе с регистрацией, затем переносится в приватный S3 Persons/User-image/{userId}/avatar.jpg; после успеха бинарные данные очищаются. Сбой сохраняет очередь и повторяет попытку через минуту. Чтение требует пользовательский JWT.

PUT /account/v1/avatar принимает avatarBase64 текущего пользователя: JPEG 384×384, до 300 КБ. Проверка выполняется до изменения данных, затем аккаунт блокируется в транзакции и изображение записывается в существующую очередь. Старый object key сбрасывается, поэтому чтение сразу возвращает новые данные; перенос в S3 выполняет AvatarTransferJob с повторными попытками. Некорректное изображение возвращает INVALID_AVATAR и сохраняет прежний аватар. Base64 маскируется в логах. Миграции не требуются.

До включения смены почты добавьте через i18n API ключи mail.emailChangeSubject, emailChangeTitle, emailChangeText для ru/en; общие codeLabel/expiry/ignore/footer уже используются регистрацией. Переводы не входят в миграции.
