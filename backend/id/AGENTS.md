# Правила проекта

- Kotlin-пакеты начинаются с `com.persons.id`.
- Один класс в файле. Следовать соседним интерфейсам, сервисам, DAO и трансформерам.
- `@Service` — только для непосредственной работы с DAO/repository. Остальную логику размещать в `component` с `@Component`.
- Базовое исключение приложения абстрактное. Конкретные классы ошибок — в `exception/impl`; не создавать базовое исключение с произвольными status/code.
- Контракт сначала меняется в `app/contract/api/schema`, затем генерируются сервер и клиенты.
- Схема БД меняется только через Flyway. `ddl-auto=validate` во всех профилях.
- Переводы, ключи и другой пользовательский контент запрещено добавлять в миграции. Миграции содержат только DDL.
- Аутентификация API — JWT. Секреты и полные токены не логировать.
- Новый функционал покрывать тестами; явные Kotlin-циклы не использовать.
- `.build`, `.gradle`, `node_modules` — локальные результаты сборки, не исходники.
