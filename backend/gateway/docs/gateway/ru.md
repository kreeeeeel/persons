# Шлюз

Next.js BFF обращаются к `/id` и `/person` на шлюзе; сам шлюз использует фиксированные внутренние адреса ID, Person и Restrictions. Адрес назначения нельзя передать запросом. Общий внутренний JWT обязателен; личность берётся из сессии ID, а не из пользовательских заголовков.

Перед вызовом Person шлюз проверяет полный запрет ACCOUNT и область операции: COMMENTS, RATINGS, LOANS, MEDIA, PROFILE или REACTIONS. Все изменяющие ручки Person покрыты проверкой контракта; неизвестная операция запрещается. Чтение также проверяет полный запрет. Получение причины блокировки, собственной личности/аватара, списка сеансов, продление сессии и выход остаются доступны. Внутренний административный API ID не проксируется. При отказе проверки применяется 503, а не разрешение.

Person сохраняет авторизацию и проверку владения данными, но не владеет запретами. Отдельный краткоживущий `X-Gateway-Authorization` с аудиторией `persons-person` подтверждает прохождение шлюза. Заголовок клиента заменяется. Прямой вызов Person без подписи отвергается до разбора multipart. Секрет `PROJECT_GATEWAY_JWT_SECRET` доступен только Person и шлюзу.

Прежние ручки администрирования аккаунтов Person сохраняют контракт. Чтение аккаунтов и завершение сеансов обращаются к ID; изменение ролей/блокировок — к Restrictions, который координирует эти операции. Встроенных повторов изменяющих запросов нет.

CMS получает аватар выбранного аккаунта через `GET /person/v1/admin/users/{id}/avatar`. Шлюз проверяет сессию и роль администратора, затем сам обращается к внутреннему ID API с сервисной подписью. JPEG возвращается с `private, no-store` и `nosniff`; отсутствие аватара сохраняет 404 для отображения инициалов. Прямой доступ BFF через `/id/internal/**` по-прежнему запрещён.

Загрузка файлов и ответы передаются потоково без накопления тела в памяти. Поддерживаются Range/206, Content-Range и длина ответа. Multipart-разбор на шлюзе отключён; максимальный запрос по времени — 10 минут. Клиентские IP-заголовки проходят существующую доверенную цепочку Nginx → BFF → шлюз → сервис. Маршруты с неоднозначным путём отвергаются.

`GET /{person|id}/v1/dynamic-properties/events` передаётся через Spring MVC async без удержания потока обработки HTTP-запроса. SSE-данные и heartbeat передаются без изменения и сбрасываются в сокет сразу; следующий пакет запрашивается только после отправки предыдущего. Отключение клиента, ошибка или завершение потока отменяют подписку на upstream. Через 10 минут соединение завершается, и EventSource переподключается за свежим снимком настроек. Проверки доступа и сервисная подпись совпадают с обычными запросами.

Настройки: `PROJECT_INTERNAL_JWT_SECRET`, `PROJECT_GATEWAY_JWT_SECRET`, `ID_BASE_URL`, `PERSON_BASE_URL`, `RESTRICTIONS_BASE_URL`. Профили dev/testing/production/tests. Базы у шлюза нет. См. [Person OpenAPI](../../../person/app/contract/api/schema/api.yaml) и [Restrictions OpenAPI](../../../restrictions/app/contract/api/schema/api.yaml).
