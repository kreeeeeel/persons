# Блокировки

Сервис владеет базой `restrictions`: причины, области запрета, автор, сроки, отзыв и версия записи. ID хранит аккаунты и роли в отдельной базе `id`; Person хранит контент в `person`. Сервис не обращается к чужим таблицам. При первом обновлении инфраструктура переносит прежние блокировки из Person с проверкой содержимого и резервной копией, сохраняя исходные таблицы для отката.

Внутренние операции требуют `X-Service-Authorization` с общим внутренним JWT. Изменения дополнительно требуют действующей сессии администратора ID. Администратор не может полностью заблокировать себя, снять с себя роль или управлять доступом, будучи полностью заблокированным. Общая блокировка строки БД сериализует изменения ролей и запретов; актуальная роль повторно проверяется после получения блокировки. Сами роли изменяются через защищённый API ID. Запрет фиксируется перед удалённым изменением роли, снятие запрета — только после успешного изменения. При частичном отказе ограничение сохраняется; операция возвращает ошибку.

Проверка сначала читает индексированную версию из PostgreSQL, затем Redis по ключу `persons:restrictions:v1:<userId>:<revision>`. Изменение или отзыв сразу делает старый ключ неприменимым. Кэш живёт не более 30 секунд и не дольше срока запрета. Некорректный кэш или отказ Redis переключает чтение на PostgreSQL; отказ PostgreSQL возвращает 503, разрешение по умолчанию не выдаётся. Просроченный запрет перестаёт действовать сразу по времени; person-worker вызывает очистку порциями до 500 записей.

Контракт: [OpenAPI](../../app/contract/api/schema/api.yaml). GET/PUT/DELETE `/v1/users/{userId}/restriction`, пакетный POST `/v1/restrictions/lookup` до 100 уникальных пользователей, POST `/v1/restrictions/expire`; PUT `/v1/users/{userId}/access` координирует роль и блокировку. Ошибки: 400, 401, 403, 409 и 503; известная ошибка ID `USER_NOT_FOUND` возвращается как 404. Чувствительные данные и тела запросов не логируются.

Настройки: `DB_URL`, `DB_USER`, `DB_PASSWORD`, `REDIS_HOST`, `REDIS_PORT`, `REDIS_PASSWORD`, `PROJECT_INTERNAL_JWT_SECRET`, `ID_BASE_URL`. Профили dev/testing/production/tests; `tests` использует изолированную H2. Реальные PostgreSQL/Redis тесты запускаются в CI. `/actuator/health` отражает доступность БД; Redis не делает сервис нездоровым, поскольку имеется рабочий резервный путь.
